### 1.2 CodeMindAgent 类实现细节

采用面向对象设计，同时提供同步与异步执行入口（实际业务中全面使用异步方法）：

```python
class CodeMindAgent:
    def __init__(self):
        # 从配置加载模型、同步工具、系统提示词
        self.llm = create_llm_from_config(...)
        self.tools = [ReadFile, SearchCode, RunCommand]   # 使用同步工具
        self.agent = create_agent(self.llm, self.tools, system_prompt=...)

    def execute(self, question: str, docs: list, summarizer_llm) -> str:
        """同步执行（向后兼容保留）"""
        ...

    async def aexecute(self, question: str, docs: list, summarizer_llm) -> str:
        """异步执行，真正非阻塞"""
        messages = self._build_messages(question, docs)
        result = await self.agent.ainvoke({"messages": messages})
        return self._extract_answer(result)

    def execute_stream(self, ...): ...
    
    async def aexecute_stream(self, ...):
        """异步流式执行，逐块产出内容"""
        async for chunk in self.agent.astream(...):
            yield self._process_stream_chunk(chunk)
```

**关键决策说明**：  
经实际验证，LangChain 1.x 中 `create_agent` 返回的 `CompiledStateGraph` 能够自动将同步工具包装为异步调用，**不需要单独创建异步工具版本**。因此最终实现删除了早期添加的 `AReadFile`、`ASearchCode`、`ARunCommand` 类，统一使用同步工具。

### 2.2 异步流式实现要点

流式生成器采用原生 `AsyncGenerator`，彻底消除线程池桥接：

```python
# agent/streaming.py
async def agenerate_agent_stream(
    agent: CodeMindAgent,
    question: str,
    docs: list,
    summarizer_llm: ChatTongyi
) -> AsyncGenerator[str, None]:
    """真正异步的流式生成器"""
    async for chunk in agent.aexecute_stream(question, docs, summarizer_llm):
        yield chunk

# app.py 端点
@app.post("/chat/stream")
async def chat_stream(request: ChatRequest):
    # ... 向量检索、上下文构建均使用异步 API
    return StreamingResponse(
        agenerate_agent_stream(agent, request.question, docs, summarizer_llm),
        media_type="text/plain"
    )
```

**兼容处理**：保留了旧版 `generate_agent_stream` 函数作为弃用桥接，内部直接调用异步版本并输出警告。

## 四、工具详解（最终实现形态）

### 4.1 ReadFile – 读取文件

**路径解析策略**（按优先级尝试）：
1. 直接路径（相对于项目根目录）
2. `repo.path` 配置的仓库路径下查找
3. 绝对路径提取文件名，再到 `repo.path` 下搜索
4. 若均失败，自动进行**文件名智能搜索**

**智能搜索逻辑**：
- 找到 **1 个**匹配 → 自动读取
- 找到 **多个**匹配 → 返回文件列表提示用户选择
- 无匹配 → 返回明确错误

**安全验证**（由 `agent/security.py` 保证）：
- 路径必须在 `agent.allowed_dirs` 或 `repo.path` 白名单内
- 不得读取 `agent.blocked_files` 中的敏感文件（如 `.env`、`*.key`）

### 4.2 SearchCode – 语义搜索

基于 Chroma 向量库进行语义检索，返回与问题最相关的代码片段。支持过滤文件类型与限制返回数量。工具本身为同步函数，由 LangChain 在异步链路中自动调度。

### 4.3 RunCommand – 执行只读命令

**支持的操作系统**：Linux、macOS、Windows

**Windows 适配策略**（已验证）：
1. 命令映射：`ls` → `dir`，`cat` → `type`，`grep` → `findstr`
2. 复杂命令（`find`、`head`、`tail`、`wc`）直接用 Python 原生实现，确保跨平台行为一致
3. Windows 内置命令（`dir`、`type`、`findstr`）使用 `shell=True` 执行（参数已严格限制），其余保持 `shell=False`

**安全措施**：
- 命令必须在 `agent.allowed_commands` 白名单中
- 禁止危险参数（如 `ls -R`、`dir /S`）防止大量输出
- 输出长度限制：
  - `find` 命令最多返回 100 条结果
  - 全局输出最多 10,000 字符，超出部分截断并警告
- 命令执行超时保护（默认 5 秒）

## 六、安全设计（三层防护）

| 层级     | 检查内容                                    | 实现位置      |
| :------- | :------------------------------------------ | :------------ |
| 路径安全 | 文件必须在 `allowed_dirs` 或 `repo.path` 内 | `security.py` |
| 文件安全 | 文件名不能匹配 `blocked_files` 黑名单模式   | `security.py` |
| 命令安全 | 基础命令在白名单内，参数不包含危险标志      | `security.py` |

### 关键实现细节

- 命令执行永远不使用 `shell=True`（Windows 内置命令除外，但已严格控制参数）
- 使用 `shlex.split()` 安全解析命令字符串
- 命令超时保护（默认 5 秒）
- 文件读取前先进行安全验证，失败则拒绝执行

## 十、阶段总结

第二阶段在 Phase01 RAG 基础上成功实现了 **Agent 自主工具调用** 与 **流式交互**，使系统从“被动检索回答”升级为“主动探索代码库”。同时通过以下工程化改进，使项目具备了生产级应用的雏形：
