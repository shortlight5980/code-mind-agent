# 风险评估与缓解方案

## 技术风险

| 风险 | 可能性 | 影响 | 缓解方案 |
|------|--------|------|----------|
| MCP Python SDK 与预期行为不一致 | 中 | 高 | 阶段一先做原型验证，尽早发现问题 |
| 符号链接在 Windows 环境下出现问题 | 中 | 中 | 提供复制脚本作为备选方案，文档中明确说明 |
| 配置共享出现问题（两个服务读取同一配置） | 低 | 中 | 配置文件设计为只读，避免写入冲突；两个服务独立加载各自的配置实例 |
| Chroma 索引文件并发访问问题 | 低 | 高 | MCP 索引操作使用文件锁；设计上索引操作不频繁；原应用是只读查询 |
| Python 版本兼容性问题 | 低 | 中 | 明确最低 Python 版本要求（3.10+）；在测试环境验证 |

## 运维风险

| 风险 | 可能性 | 影响 | 缓解方案 |
|------|--------|------|----------|
| 需要同时管理两个服务 | 中 | 中 | 提供 docker-compose 一键启动方案；编写启动/停止脚本 |
| 环境变量配置不一致 | 低 | 中 | 两个服务使用相同的 .env 文件；提供配置检查脚本 |
| 日志分散在两个地方 | 低 | 低 | 使用相同的日志格式和目录结构；提供日志聚合说明 |

## 回滚策略

### 完整回滚

如果迁移过程中出现严重问题，可以按以下步骤回滚：

1. 停止 MCP 服务
2. 删除 `mcp/` 目录
3. 恢复 `requirements.txt`
4. 原应用不受影响，继续正常工作

### 单个工具回滚

如果某个工具迁移后出现问题：

1. 在 `mcp/server.py` 中注释掉该工具的注册
2. Claude Desktop 侧不再使用该 MCP 工具
3. 原应用中的该工具继续正常工作

## 监控要点

迁移后建议关注：

1. **MCP服务稳定性** - 进程是否持续运行
2. **工具调用成功率** - 是否有调用失败
3. **原应用性能** - 核心检索是否受影响
4. **索引一致性** - MCP写入索引后，原应用是否能正常查询

## 安全审查清单

- [ ] 路径安全验证逻辑完全复用原有实现
- [ ] 命令白名单机制保持不变
- [ ] 敏感文件检查保持不变
- [ ] MCP工具不能访问RetrieveAndSummarize（设计上就不提供）
- [ ] 环境变量传递中不包含敏感信息（除了必要的API Key）
