## 详细修改

### 1. `agent/streaming.py` 修改
- 删除 `generate_agent_stream()`：该函数已明确标记为"已弃用"，内部直接调用 `agenerate_agent_stream()`，无实际价值。
- 删除 `process_sync_stream()`：该函数未在任何地方调用，且项目已全面转向异步流式处理。

### 2. `agent/agent.py` 修改
- 删除 `create_codemind_agent()`：该函数仅为向后兼容，返回 `CodeMindAgent.agent` 属性。新代码应直接使用 `CodeMindAgent` 类。
- 删除 `run_agent_with_summary()`：该函数包装了 `CodeMindAgent.execute()`，保留向后兼容性。检查发现无外部调用。

### 3. `rag/context_builder.py` 修改
- 删除 `fuse_documents()` 系列方法：这些方法提供了多文档融合策略，但当前仅实现了简单拼接，且未在实际流程中使用。相关 TODO 注释表明为预留功能。
- 保留核心的 `build_context()`、`abuild_context()` 等方法，不影响现有 RAG 流程。

### 4. `agent/__init__.py` 修改
- 更新导出列表，移除已删除函数的导出项：
  - `generate_agent_stream`
  - `create_codemind_agent`
  - `run_agent_with_summary`
  - `process_sync_stream`
- 保持 `CodeMindAgent`、安全工具和 `process_chunk` 的导出不变。

## 影响分析

### 正面影响
1. **代码简洁性提升**：移除 7 个未使用/废弃函数，减少代码量约 120 行。
2. **维护成本降低**：消除了潜在的混淆点，新开发者无需了解已弃用的兼容函数。
3. **性能微优化**：减少了不必要的函数调用层级（如 `generate_agent_stream` 包装器）。
4. **架构清晰度**：强化了 `CodeMindAgent` 类作为统一入口的设计模式。

### 兼容性影响

3. **测试验证**：通过语法检查确认无导入错误，关键文件编译正常。

### 风险控制

## 技术决策

### 删除而非注释的原因
1. **版本控制透明**：Git 历史完整记录删除操作，可随时恢复。
2. **代码可读性**：避免遗留大量 `# TODO` 或 `# DEPRECATED` 注释干扰阅读。
3. **YAGNI 原则**：当前未使用的功能，待真正需要时可重新实现（可能更优）。

### 保留 `PromptManager` API 方法的原因
1. **管理接口定位**：这些方法设计用于动态提示词管理，可能在未来通过管理界面调用。
2. **功能完整性**：作为提示词管理系统的一部分，保持 API 完整性。
3. **无维护成本**：这些方法实现简单，保留不影响代码质量。
