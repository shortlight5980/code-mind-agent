# 项目研究发现

## 当前架构分析

### 现有检索流程
```
用户问题
    ↓
查询改写 (关键词提取 + 答案猜测)
    ↓
向量检索 (Chroma)
    ├── doc: k=5
    └── code: k=10
    ↓
结果汇总
    ↓
LLM摘要
    ↓
返回给Agent
```

### 关键文件
| 文件 | 作用 |
|------|------|
| `agent/tools/retrieve_and_summarize.py` | 主检索工具，已有TODO注释标记需要添加混合检索 |
| `services/service_manager.py` | 服务单例，管理vectordb、llms等 |
| `scripts/index_repo.py` | 索引构建脚本，AST感知的代码切分 |
| `config.yml` | 配置文件 |

### 现有配置
```yaml
chroma:
  persist_dir: "./chroma_db"
  retrieval_k:
    docs: 5
    codes: 10
```

## RNN适用性结论

**不推荐使用RNN/LSTM**，原因：
1. 当前已有摘要层用LLM进行融合，效果更好
2. 检索是单轮的，无强序列依赖
3. 增加复杂度和维护成本
4. 无明显收益

## 代码检索特殊性

代码检索与文档检索的区别：
1. **精确匹配重要**: 函数名、类名、变量名的精确匹配
2. **结构信息**: 调用关系、继承关系
3. **质量特征**: 块长度、复杂度、注释比例
4. **标识符敏感**: 驼峰命名、下划线命名

## BM25对代码检索的价值

BM25在以下场景优于向量检索：
- 用户查询包含具体函数名/类名
- 需要精确匹配API名称
- 短查询场景
