# 01. Agent 原理入门

在 Phase01 中，我们的系统是"被动"的——它只能基于检索到的代码片段回答问题。如果检索结果中没有足够的信息，它就无法进一步探索。

在 Phase02 中，我们引入 **Agent（智能体）**，让系统变得"主动"——它可以自主决定调用什么工具来获取更多信息！

## 什么是 Agent？

### 从 RAG 到 Agent

**Phase01（RAG）**：
```
用户问题 → 检索代码 → 直接生成回答
          ↑
      只能用已检索到的信息
```

**Phase02（Agent）**：
```
用户问题 → 检索代码 → Agent 思考 → 调用工具 → 观察结果 → 继续思考... → 最终回答
                      ↑                              ↑
              自主决定做什么                获取新信息
```

### Agent 的核心组件

| 组件 | 作用 |
|------|------|
| **LLM（大脑）** | 思考、决策、生成回答 |
| **Tools（工具）** | Agent 可以调用的能力（读取文件、搜索代码等） |
| **Agent Executor** | 管理 LLM 与 Tools 之间的交互循环 |

## ReAct 模式详解

ReAct（Reasoning + Acting）是 Agent 的经典模式，它的流程是：

```
思考（Thought）→ 行动（Action）→ 观察（Observation）→ 思考... → 最终答案
```

### 具体例子

假设用户问："这个项目的日志系统是怎么实现的？"

Agent 的执行过程可能是：

**第 1 轮：**
```
思考：用户问的是日志系统，我需要先看看 utils/logger.py 文件
行动：ReadFile
行动输入：{"file_path": "utils/logger.py"}
```

**第 2 轮：**
```
思考：我已经看到了 logger.py 的内容，现在需要观察结果
观察：（ReadFile 返回了文件内容）
思考：很好，我现在有足够的信息来回答了
最终答案：这个项目使用单例模式的日志系统...
```

### LangChain 1.0 的新 Agent API

在 LangChain 1.0 之前，创建 Agent 需要：
1. 使用 `create_react_agent` 创建 agent
2. 使用 `AgentExecutor` 包装
3. 调用 `agent_executor.invoke()`

在 LangChain 1.0 中，一切变得更简单：

```python
from langchain.agents import create_agent

# 一步创建！
agent = create_agent(
    model=llm,
    tools=tools,
    system_prompt="你是一个有用的助手"
)

# 直接调用，无需 AgentExecutor
response = agent.invoke({
    "messages": [{"role": "user", "content": "你好！"}]
})
```

**新 API 的优势**：
- ✅ 更简洁：一个函数搞定
- ✅ 更统一：所有 Agent 类型都用这个入口
- ✅ 更易用：返回的 agent 直接有 invoke/stream 方法

## 本项目的 Agent 架构

### 数据流向

```
用户问题
    ↓
Chroma 检索 Top-7 代码片段
    ↓
总结模块对检索结果进行总结
    ↓
Agent 初始化（带总结后的上下文）
    ↓
┌─────────────────────────────────────┐
│  Agent 循环：                        │
│  1. 思考（LLM 决策）                │
│  2. 调用工具（ReadFile/Search等）   │
│  3. 观察结果（工具返回）            │
│  4. 重复直到完成                    │
└─────────────────────────────────────┘
    ↓
最终回答
```

### 为什么先总结再 Agent？

你可能注意到了，我们不是直接把检索结果丢给 Agent，而是先总结一下。为什么？

1. **减少 Token 消耗**：7 个代码片段可能很长，总结后更精炼
2. **提高效率**：Agent 不需要处理冗余信息
3. **降低成本**：Token 就是钱，省一点是一点

### 工具列表

| 工具 | 功能 |
|------|------|
| **ReadFile** | 读取指定文件内容，支持行号范围 |
| **SearchCode** | 在代码库中搜索关键词或正则表达式 |
| **RunCommand** | 执行只读 shell 命令（ls、cat、grep 等） |

## 关键设计决策

### 1. 安全第一

Agent 可以读取文件、执行命令，这很强大但也很危险！所以我们设计了三层安全检查：

- **路径白名单**：只允许访问指定目录
- **文件黑名单**：禁止读取 .env、*.key 等敏感文件
- **命令白名单**：只允许执行 ls、cat 等安全命令

### 2. 降级方案

Agent 可能会失败（比如工具调用出错、LLM 解析失败），所以我们有降级方案：

```
尝试 Agent → 失败 → 使用总结后的上下文直接回答
```

### 3. 详细日志

为了调试和学习，我们添加了详细的日志输出：

- **Debug 级别**：完整提示词、模型返回、向量检索结果
- **Info 级别**：工具调用、关键流程步骤、最终答案
