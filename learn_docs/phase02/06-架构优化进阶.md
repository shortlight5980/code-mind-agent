# 06. 架构优化进阶

在本文档中，我们将学习项目中的几个重要架构优化模块：
1. **服务单例管理器** - 统一管理所有服务的生命周期
2. **RAG 上下文构建器** - 封装 RAG 上下文处理逻辑
3. **提示词管理器** - 管理提示词的版本、多语言和多场景
4. **Agent 流式处理** - 将流式处理逻辑抽取到 Agent 模块
5. **全面异步化改造** - 使用真正的异步 API 提升并发性能

## 一、服务单例管理器

### 为什么需要服务管理器？

在之前的 `app.py` 中，我们使用一个全局的 `services` 字典来存储服务对象，存在以下问题：
- 服务创建逻辑混杂在 `app.py` 中
- 没有统一的生命周期管理
- 访问服务时需要使用字典键，容易出错
- 无法保证单例模式

### 解决方案：`ServiceManager` 类

**文件位置**: `services/service_manager.py`

### 核心设计

```python
class ServiceManager:
    """服务单例管理器"""

    # 单例实例
    _instance: Optional['ServiceManager'] = None

    # 服务存储
    _services: Dict[str, Any] = {}

    # 初始化标志
    _initialized: bool = False

    def __new__(cls) -> 'ServiceManager':
        """单例模式实现"""
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
```

### 关键特性

#### 1. 单例模式
确保整个应用中只有一个 `ServiceManager` 实例：
```python
# 获取单例实例
service_manager = ServiceManager.get_instance()
```

#### 2. 属性化访问
将常用服务作为属性提供，使用更方便：
```python
# 旧方式（字典访问）
vectordb = services["vectordb"]
llm = services["llm"]

# 新方式（属性访问）
vectordb = service_manager.vectordb
llm = service_manager.llm
agent = service_manager.agent
```

#### 3. 统一初始化
所有服务的创建逻辑都封装在 `initialize()` 方法中：
```python
def initialize(self) -> None:
    """初始化所有服务"""
    Config.load()
    self._init_vectordb()
    self._init_llm()
    self._init_summarizer_llm()
    self._init_agent()
    self._initialized = True
```

每个服务都有独立的初始化方法：
- `_init_vectordb()` - 初始化向量数据库
- `_init_llm()` - 初始化主 LLM
- `_init_summarizer_llm()` - 初始化摘要 LLM
- `_init_agent()` - 初始化 Agent

#### 4. 生命周期管理
```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    """FastAPI lifespan事件处理器"""

    # 关闭时清理
    # TODO: 使用 asyncio.to_thread() 包装同步清理，避免阻塞事件循环

    logger.info("服务已清理")
```

## 二、RAG 上下文构建器

### 为什么需要上下文构建器？

在 RAG 系统中，上下文处理是一个独立的子域，包含：
- 文档拼接与格式化
- 基于问题的摘要压缩
- 多文档融合策略

这些逻辑之前散落在 `app.py` 和 `utils/summarizer.py` 中，不够内聚。

### 解决方案：`RAGContextBuilder` 类

**文件位置**: `rag/context_builder.py`

### 核心功能

#### 1. 上下文构建主方法
```python
def build_context(
    self,
    docs: List[Document],
    question: Optional[str] = None,
    enable_summarization: bool = True
) -> ProcessedContext:
    """构建 RAG 上下文"""
    # 1. 构建原始上下文
    raw_context = self._concat_documents(docs)

    # 2. 生成来源列表
    sources = self._extract_sources(docs)

    # 3. 如果启用摘要且有问题，则进行摘要压缩
    summarized_context = raw_context
    if enable_summarization and question:
        summarized_context = self._compress_context(raw_context, question)

    return ProcessedContext(
        raw_context=raw_context,
        summarized_context=summarized_context,
        sources=sources
    )
```

#### 2. 异步上下文构建
```python
async def abuild_context(
    self,
    docs: List[Document],
    question: Optional[str] = None,
    enable_summarization: bool = True
) -> ProcessedContext:
    """异步版本：构建 RAG 上下文"""
    # 1. 构建原始上下文
    raw_context = self._concat_documents(docs)

    # 2. 生成来源列表
    sources = self._extract_sources(docs)

    # 3. 如果启用摘要且有问题，则进行摘要压缩（异步）
    summarized_context = raw_context
    if enable_summarization and question:
        summarized_context = await self._acompress_context(raw_context, question)

    return ProcessedContext(
        raw_context=raw_context,
        summarized_context=summarized_context,
        sources=sources
    )
```

#### 3. 使用数据类返回结果
```python

    summarized_context: str
    sources: List[Dict[str, str]]
```

#### 4. 多文档融合策略（预留）

```python
def fuse_documents(
    self,
    docs: List[Document],
```

## 三、提示词管理器

### 为什么需要提示词管理器？

之前的提示词存在以下问题：
- 硬编码在代码中，难以调整
- 不支持版本管理
- 不支持多语言
- 不支持多场景模板

### 解决方案：`PromptManager` 类

**文件位置**: `prompts/prompt_manager.py`

### 核心设计

#### 1. 枚举定义
```python
class PromptScenario(Enum):
    """提示词场景枚举"""
    CODE_EXPLANATION = "code_explanation"
    BUG_FIX = "bug_fix"
    ARCHITECTURE_DESIGN = "architecture_design"

class PromptLanguage(Enum):
    """提示词语言枚举"""
```

#### 2. 版本管理
```python
@dataclass
class PromptVersion:
    """提示词版本信息"""

    scenario: PromptScenario
    language: PromptLanguage
    template: str
    input_variables: list
    description: str
```

#### 3. 获取提示词
```python
def get_prompt(
    self,
    scenario: PromptScenario = PromptScenario.GENERAL_QA,
    language: PromptLanguage = PromptLanguage.ZH_CN,
    version: Optional[str] = None
```

## 四、Agent 流式处理

### 为什么需要抽取流式处理逻辑？

之前的流式处理函数定义在 `app.py` 中，存在以下问题：
- Agent 的调用方式（同步/流式）属于 Agent 模块的职责
- 消息格式化规则应该与 Agent 逻辑放在一起
- API 层应该只负责路由和请求响应处理

### 解决方案：`agent/streaming.py`

**文件位置**: `agent/streaming.py`

### 核心功能

#### 1. 消息转换规则
```python
def process_chunk(chunk: Dict[str, Any]) -> Optional[Dict[str, Any]]:
    """处理 Agent 流式输出的 chunk，进行消息格式化"""
    message: Dict[str, Any] = {}

    if chunk["type"] == "human":
        return None

    elif chunk["type"] == "ai":
        message["type"] = "ai"
        message["content"] = chunk["data"]["content"]
        message["id"] = chunk["data"]["id"]

        # 提取并简化 tool_calls
        raw_tool_calls = chunk["data"].get("tool_calls", [])
        simplified_tool_calls = []
        for tc in raw_tool_calls:
            simplified_tool_calls.append({
                "id": tc["id"],
                "name": tc["name"],
                "args": tc["args"]
            })
        message["tool_calls"] = simplified_tool_calls

    elif chunk["type"] == "tool":
        message["type"] = "tool"
        message["content"] = chunk["data"]["content"]
        message["tool_call_id"] = chunk["data"]["tool_call_id"]
        message["name"] = chunk["data"]["name"]

    return message if message else None
```

#### 2. 真正的异步流式生成
```python
async def agenerate_agent_stream(
    agent: CodeMindAgent,
    question: str,
    docs: list,
    summarizer_llm: ChatTongyi
) -> AsyncGenerator[str, None]:
    """生成 Agent 流式响应（真正异步版本）"""
    logger.info("启动真正的异步 Agent 流...")

    try:
        async for chunk in agent.aexecute_stream(question, docs, summarizer_llm):
            message = process_chunk(chunk)
            if message:
                yield f"data: {json.dumps(message, ensure_ascii=False)}\n\n"

        yield "data: [DONE]\n\n"

    except Exception as e:
        logger.error(f"异步流式生成失败: {e}")
        yield f"\n[Error] 异步流式生成失败: {str(e)}\n"
```

#### 3. 异步生成器用于单个结果
```python
async def single_result_generator(text: str) -> AsyncGenerator[str, None]:
    """异步生成单个结果的生成器，用于非流式回退场景"""
    yield text
```

#### 4. 在 app.py 中的使用
```python
from agent.streaming import agenerate_agent_stream

@app.post("/chat/stream")
async def chat_stream(query: Query):
    """问答接口，支持Agent模式（流式）"""
    # 异步检索文档
    docs = await vectordb.asimilarity_search(query.question, k=retrieval_k)

    if agent_enabled and agent is not None:
        logger.info("使用Agent模式（异步流式）...")
        return StreamingResponse(
            agenerate_agent_stream(agent, query.question, docs, summarizer_llm),
            media_type="text/plain"
        )
```

## 五、全面异步化改造

### 为什么需要异步化？

在 FastAPI 应用中，如果使用 `async def` 定义路由函数但内部执行同步阻塞操作，会导致：
- 无法获得真正异步的性能优势
- 高并发下会受到线程池大小限制
- 资源利用率不如真正的异步 I/O

### 异步 API 命名规范

LangChain 的异步 API 通常在同步 API 前加前缀 `a`：

| 同步 API | 异步 API |
|---------|---------|
| `invoke()` | `ainvoke()` |
| `stream()` | `astream()` |
| `similarity_search()` | `asimilarity_search()` |

### 异步化层级

#### 1. 总结模块异步化

**文件位置**: `utils/summarizer.py`

```python
async def asummarize_context(question: str, raw_context: str, summarizer_llm: ChatTongyi) -> str:
    """异步版本：使用总结模型对原始上下文进行总结"""
    prompt = SUMMARIZER_PROMPT_TEMPLATE.format(input=question, context=raw_context)
    response = await summarizer_llm.ainvoke(prompt)
    return response.content if hasattr(response, 'content') else str(response)
```

#### 2. Agent 执行异步化

**文件位置**: `agent/agent.py`

```python
async def aexecute(
    self,
    question: str,
    raw_docs: Optional[List[Any]] = None,
    summarizer_llm: Optional[ChatTongyi] = None
) -> Dict[str, Any]:
    """异步版本：非流式执行 Agent 任务"""
    # 步骤 1：构建上下文
    summarized_context = ""
    if raw_docs is not None and summarizer_llm is not None:
        raw_context = build_context(raw_docs)
        summarized_context = await asummarize_context(question, raw_context, summarizer_llm)

    # 步骤 2：构建用户消息
    user_message_content = self._build_user_message(question, summarized_context)

    # 步骤 3：异步运行 Agent
    response = await self.agent.ainvoke({
        "messages": [{"role": "user", "content": user_message_content}]
    })

    return {
        "answer": response["messages"][-1].content,
        "summarized_context": summarized_context
    }
```

```python
async def aexecute_stream(
    self,
    question: str,
    raw_docs: Optional[List[Any]] = None,
    summarizer_llm: Optional[ChatTongyi] = None,
    context: Optional[Dict[str, Any]] = None
) -> AsyncGenerator[Dict[str, Any], None]:
    """异步版本：流式执行 Agent 任务"""
    # 步骤 1：构建上下文
    summarized_context = ""
    if raw_docs is not None and summarizer_llm is not None:
        raw_context = build_context(raw_docs)
        summarized_context = await asummarize_context(question, raw_context, summarizer_llm)

    # 步骤 2：构建用户消息
    user_message_content = self._build_user_message(question, summarized_context)

    # 步骤 3：异步流式运行 Agent
    input_dict = {
        "messages": [{"role": "user", "content": user_message_content}]
    }
    async for chunk in self.agent.astream(input_dict, stream_mode="values"):
        last_message = chunk["messages"][-1]
        yield message_to_dict(last_message)
```

#### 4. API 层完全异步化

**文件位置**: `app.py`

```python
@app.post("/chat")
async def chat(query: Query):
    """问答接口，支持Agent模式（非流式，真正异步）"""
    # 1. 异步检索相关文档
    docs = await vectordb.asimilarity_search(query.question, k=retrieval_k)

    # 2. 检查是否使用Agent
    if agent_enabled and agent is not None:
        # 异步执行 Agent
        result = await agent.aexecute(
            question=query.question,
            raw_docs=docs,
            summarizer_llm=summarizer_llm
        )
        return {
            "answer": result.get("answer", ""),
            "sources": result.get("sources", []),
            "agent_mode": True,
            "summarized_context": result.get("summarized_context", "")
        }
    else:
        # 异步构建上下文
        context_builder = RAGContextBuilder(summarizer_llm)
        processed_context = await context_builder.abuild_context(
            docs=docs,
            question=query.question,
            enable_summarization=True
        )

        # 异步调用 LLM
        prompt = prompt_template.format(
            context=processed_context.summarized_context,
            question=query.question
        )
        response = await llm.ainvoke(prompt)
        answer = response.content if hasattr(response, 'content') else str(response)

        return {
            "answer": answer,
            "sources": processed_context.sources,
            "agent_mode": False,
            "summarized_context": processed_context.summarized_context
        }
```

### 完整异步化层级总览

| 层级 | 异步化方式 |
|------|-----------|
| **API 路由层** | `/chat`、`/chat/stream` 全异步 |
| **向量检索** | `asimilarity_search()` |
| **LLM 调用** | `ainvoke()` |
| **Agent 执行** | `aexecute()`、`aexecute_stream()` |
| **上下文构建** | `abuild_context()` |
| **总结模块** | `asummarize_context()` |
| **流式响应** | `agenerate_agent_stream()` + 异步生成器 |
| **Agent 工具** | `ReadFile`、`SearchCode`、`RunCommand` (LangChain 自动处理异步) |

### 性能优势

1. **非阻塞 I/O**: 所有 I/O 操作都不会阻塞事件循环
2. **更高并发**: 异步 I/O 允许在等待 I/O 时处理其他请求
3. **资源利用率**: 更好地利用系统资源，减少线程切换开销
4. **可扩展性**: 高并发场景下性能表现更优

## 六、架构设计原则总结

### 1. 单一职责原则 (SRP)
- 每个类/模块只负责一个功能
- `ServiceManager` - 只负责服务管理
- `RAGContextBuilder` - 只负责上下文处理
- `PromptManager` - 只负责提示词管理

### 2. 开闭原则 (OCP)
- 对扩展开放，对修改关闭
- `PromptManager` 可以轻松添加新场景、新语言
- `RAGContextBuilder` 可以轻松添加新的融合策略

### 3. 依赖倒置原则 (DIP)
- 高层模块不依赖低层模块，都依赖抽象
- `app.py` 依赖 `ServiceManager` 接口，而不是具体的服务创建逻辑

### 4. 关注点分离
- API 层 (`app.py`) - 只负责路由和请求响应
- 服务层 (`services/`) - 负责服务生命周期
- 业务层 (`agent/`, `rag/`) - 负责业务逻辑
- 工具层 (`utils/`) - 提供通用工具

### 5. 异步优先原则
- 所有 I/O 操作优先使用异步 API
- 使用 `asyncio.to_thread()` 处理无法异步化的同步操作
- 使用异步生成器处理流式响应
