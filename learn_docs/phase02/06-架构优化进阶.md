# 06. 架构优化进阶

在本文档中，我们将学习项目中的几个重要架构优化模块：
1. **服务单例管理器** - 统一管理所有服务的生命周期
2. **RAG 上下文构建器** - 封装 RAG 上下文处理逻辑
3. **提示词管理器** - 管理提示词的版本、多语言和多场景
4. **Agent 流式处理** - 将流式处理逻辑抽取到 Agent 模块

## 一、服务单例管理器

### 为什么需要服务管理器？

在之前的 `app.py` 中，我们使用一个全局的 `services` 字典来存储服务对象，存在以下问题：
- 服务创建逻辑混杂在 `app.py` 中
- 没有统一的生命周期管理
- 访问服务时需要使用字典键，容易出错
- 无法保证单例模式

### 解决方案：`ServiceManager` 类

**文件位置**: `services/service_manager.py`

### 核心设计

```python
class ServiceManager:
    """服务单例管理器"""

    # 单例实例
    _instance: Optional['ServiceManager'] = None

    # 服务存储
    _services: Dict[str, Any] = {}

    # 初始化标志
    _initialized: bool = False

    def __new__(cls) -> 'ServiceManager':
        """单例模式实现"""
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance
```

### 关键特性

#### 1. 单例模式
确保整个应用中只有一个 `ServiceManager` 实例：
```python
# 获取单例实例
service_manager = ServiceManager.get_instance()
```

#### 2. 属性化访问
将常用服务作为属性提供，使用更方便：
```python
# 旧方式（字典访问）
vectordb = services["vectordb"]
llm = services["llm"]

# 新方式（属性访问）
vectordb = service_manager.vectordb
llm = service_manager.llm
agent = service_manager.agent
```

#### 3. 统一初始化
所有服务的创建逻辑都封装在 `initialize()` 方法中：
```python
def initialize(self) -> None:
    """初始化所有服务"""
    Config.load()
    self._init_vectordb()
    self._init_llm()
    self._init_summarizer_llm()
    self._init_agent()
    self._initialized = True
```

每个服务都有独立的初始化方法：
- `_init_vectordb()` - 初始化向量数据库
- `_init_llm()` - 初始化主 LLM
- `_init_summarizer_llm()` - 初始化摘要 LLM
- `_init_agent()` - 初始化 Agent

#### 4. 生命周期管理
```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    """FastAPI lifespan事件处理器"""
    global service_manager
    try:
        service_manager = ServiceManager.get_instance()
        service_manager.initialize()
    except Exception as e:
        logger.error(f"初始化失败: {e}")
    yield
    # 关闭时清理
    service_manager.cleanup()
    logger.info("服务已清理")
```

## 二、RAG 上下文构建器

### 为什么需要上下文构建器？

在 RAG 系统中，上下文处理是一个独立的子域，包含：
- 文档拼接与格式化
- 基于问题的摘要压缩
- 多文档融合策略

这些逻辑之前散落在 `app.py` 和 `utils/summarizer.py` 中，不够内聚。

### 解决方案：`RAGContextBuilder` 类

**文件位置**: `rag/context_builder.py`

### 核心功能

#### 1. 上下文构建主方法
```python
def build_context(
    self,
    docs: List[Document],
    question: Optional[str] = None,
    enable_summarization: bool = True
) -> ProcessedContext:
    """构建 RAG 上下文"""
    # 1. 构建原始上下文
    raw_context = self._concat_documents(docs)

    # 2. 生成来源列表
    sources = self._extract_sources(docs)

    # 3. 如果启用摘要且有问题，则进行摘要压缩
    summarized_context = raw_context
    if enable_summarization and question:
        summarized_context = self._compress_context(raw_context, question)

    return ProcessedContext(
        raw_context=raw_context,
        summarized_context=summarized_context,
        sources=sources
    )
```

#### 2. 使用数据类返回结果
```python
@dataclass
class ProcessedContext:
    """处理后的上下文结果"""
    raw_context: str
    summarized_context: str
    sources: List[Dict[str, str]]
```

#### 3. 多文档融合策略（预留）
```python
def fuse_documents(
    self,
    docs: List[Document],
    strategy: str = "simple_concat"
) -> str:
    """多文档融合策略"""
    if strategy == "simple_concat":
        return self._concat_documents(docs)
    elif strategy == "weighted":
        return self._fuse_weighted(docs)
    elif strategy == "rerank":
        return self._fuse_rerank(docs)
```

## 三、提示词管理器

### 为什么需要提示词管理器？

之前的提示词存在以下问题：
- 硬编码在代码中，难以调整
- 不支持版本管理
- 不支持多语言
- 不支持多场景模板

### 解决方案：`PromptManager` 类

**文件位置**: `prompts/prompt_manager.py`

### 核心设计

#### 1. 枚举定义
```python
class PromptScenario(Enum):
    """提示词场景枚举"""
    CODE_EXPLANATION = "code_explanation"
    BUG_FIX = "bug_fix"
    ARCHITECTURE_DESIGN = "architecture_design"
    CODE_REVIEW = "code_review"
    GENERAL_QA = "general_qa"

class PromptLanguage(Enum):
    """提示词语言枚举"""
    ZH_CN = "zh-CN"
    EN_US = "en-US"
```

#### 2. 版本管理
```python
@dataclass
class PromptVersion:
    """提示词版本信息"""
    version: str
    scenario: PromptScenario
    language: PromptLanguage
    template: str
    input_variables: list
    description: str
    created_at: str
```

#### 3. 获取提示词
```python
def get_prompt(
    self,
    scenario: PromptScenario = PromptScenario.GENERAL_QA,
    language: PromptLanguage = PromptLanguage.ZH_CN,
    version: Optional[str] = None
) -> LangChainPromptTemplate:
    """获取提示词模板"""
    key = self._get_prompt_key(scenario, language, version)
    prompt_version = self._prompts[key]

    return LangChainPromptTemplate(
        input_variables=prompt_version.input_variables,
        template=prompt_version.template
    )
```

#### 4. 使用示例
```python

    scenario=PromptScenario.GENERAL_QA,
    language=PromptLanguage.ZH_CN

    context=processed_context.summarized_context,
    question=query.question
```

## 四、Agent 流式处理

### 为什么需要抽取流式处理逻辑？

之前的 `generate_stream` 函数和 `process_chunk` 函数定义在 `app.py` 中，存在以下问题：
- Agent 的调用方式（同步/流式）属于 Agent 模块的职责
- 消息格式化规则应该与 Agent 逻辑放在一起
- API 层应该只负责路由和请求响应处理

### 解决方案：`agent/streaming.py`

**文件位置**: `agent/streaming.py`

### 核心功能

#### 1. 消息转换规则
```python
def process_chunk(chunk: Dict[str, Any]) -> Optional[Dict[str, Any]]:
    """处理 Agent 流式输出的 chunk，进行消息格式化"""
    message: Dict[str, Any] = {}

    if chunk["type"] == "human":
        return None

    elif chunk["type"] == "ai":
        message["type"] = "ai"
        message["content"] = chunk["data"]["content"]
        message["id"] = chunk["data"]["id"]

        # 提取并简化 tool_calls
        raw_tool_calls = chunk["data"].get("tool_calls", [])
        simplified_tool_calls = []
        for tc in raw_tool_calls:
            simplified_tool_calls.append({
                "id": tc["id"],
                "name": tc["name"],
                "args": tc["args"]
            })
        message["tool_calls"] = simplified_tool_calls

    elif chunk["type"] == "tool":
        message["type"] = "tool"
        message["content"] = chunk["data"]["content"]
        message["tool_call_id"] = chunk["data"]["tool_call_id"]
        message["name"] = chunk["data"]["name"]

    return message if message else None
```

#### 2. 异步/同步桥接
```python
async def generate_agent_stream(
    agent: CodeMindAgent,
    question: str,
    docs: list,
    summarizer_llm: ChatTongyi
) -> AsyncGenerator[str, None]:
    """生成 Agent 流式响应（异步/同步桥接）"""
    # 创建线程安全的队列
    data_queue = queue.Queue()

    # 在独立线程中运行同步生成器
    def run_sync_generator():
        try:
            for chunk in agent.execute_stream(question, docs, summarizer_llm):
                data_queue.put(chunk)
        except Exception as e:
            data_queue.put(e)
        finally:
            data_queue.put(None)

    # 启动线程
    loop = asyncio.get_running_loop()
    loop.run_in_executor(None, run_sync_generator)

    # 异步从队列中拉取数据
    while True:
        item = await asyncio.to_thread(data_queue.get)

        if item is None:
            yield "data: [DONE]\n\n"
            break

        if isinstance(item, Exception):
            logger.error(f"流式生成失败: {item}")
            yield f"\n[Error] 流式生成失败: {str(item)}\n"
            break

        # 处理 chunk
        message = process_chunk(item)

        if message:
            yield f"data: {json.dumps(message, ensure_ascii=False)}\n\n"
```

#### 3. 在 app.py 中的使用

## 五、架构设计原则总结

### 1. 单一职责原则 (SRP)
- 每个类/模块只负责一个功能
- `ServiceManager` - 只负责服务管理
- `RAGContextBuilder` - 只负责上下文处理
- `PromptManager` - 只负责提示词管理

### 2. 开闭原则 (OCP)
- 对扩展开放，对修改关闭
- `PromptManager` 可以轻松添加新场景、新语言
- `RAGContextBuilder` 可以轻松添加新的融合策略

### 3. 依赖倒置原则 (DIP)
- 高层模块不依赖低层模块，都依赖抽象
- `app.py` 依赖 `ServiceManager` 接口，而不是具体的服务创建逻辑

### 4. 关注点分离
- API 层 (`app.py`) - 只负责路由和请求响应
- 服务层 (`services/`) - 负责服务生命周期
- 业务层 (`agent/`, `rag/`) - 负责业务逻辑
- 工具层 (`utils/`) - 提供通用工具
